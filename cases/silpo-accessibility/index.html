Silpo — WCAG 2.1 guidelines and a design audit for web and app.

Silpo is one of Ukraine’s largest grocery retailers: hundreds of stores, a busy e-commerce site and a mobile app with millions of installs. At that scale, every accessibility gap reaches a lot of real people. Our team wrote Silpo’s own accessibility guidelines in Ukrainian, audited the design mockups of both products against WCAG 2.1, and turned the findings into a phased rollout plan for design, development and content teams.

Two goals: a shared standard and a realistic plan.

Silpo’s product teams had no common reference for accessibility. Each designer and developer relied on their own reading of WCAG, so the same issues kept returning on new screens.

The project had two goals. First, give the teams their own guideline for web and mobile, written in Ukrainian and tied to Silpo’s real screens. Second, check the current mockups and build a step-by-step plan that the teams could actually put into sprints. Every audit finding links back to a guideline page that explains the criterion and how to fix it.

I worked on this as a product designer in the audit team. The project was organised around ownership: each criterion has one owner — design, development, marketing or content — so no finding is left as “somebody should fix this”. Findings from design-owned criteria were checked in the mockups with contrast plugins in Figma, and keyboard behaviour was checked on the live site.

Four deliverables.

  1. Web accessibility guideline13 guidelines and 78 WCAG 2.1 success criteria. For each criterion: level, 1–3 W3C techniques, Silpo-specific examples and a “How to check” section.
  2. Mobile app accessibility guideline52 practices in 12 categories, each typed as “Must”, “Should”, “Never” or “Avoid”. Separate notes for iOS and Android, plus a testing procedure.
  3. Website auditHome, category catalogue, product listing and product page, desktop and mobile widths, checked against six design-owned criteria: 1.3.4, 1.4.1, 1.4.3, 1.4.6, 2.4.7, 2.5.5.
  4. Mobile app auditHome, addresses, catalogue, profile, QR card, orders, self-checkout, store stock and more — checked for contrast, colour-only meaning, target size and focus states.

What the audit found.

  • Brand colours fail contrast (1.4.3)White text on Silpo’s orange and green gave 2.44 : 1 instead of 4.5 : 1 — on discounts, loyalty points, bonuses, promo labels and order statuses. Grey secondary text sat at 3.58 : 1. On the app, a disabled “Go to payment” button in self-checkout dropped to 1.64 : 1.
  • Colour as the only signal (1.4.1)A green dot marked personal offers, a second price in green had no explanation, order statuses and “In stock / Running low” differed only by colour, and the active tab in the tab bar changed colour only.
  • Tap targets too small (2.5.5)Most buttons, chips, tabs and icons were 24–40 px; footer links were 17 px high and breadcrumbs 16 px. The audit set 44 × 44 px as the floor on both platforms, even though WCAG 2.1 lists it as AAA.
  • No visible focus (2.4.7)Almost no element on the site or in the app had a focus state — header, cards, carousels, pagination, footer, tab bar.
  • A keyboard trap (2.1.2)The search field in the site header held keyboard focus: pressing Tab did not move on to the next element.

Fixes that keep the brand.

  • ContrastA screen-by-screen table of every failing element with its current ratio, checked with a Figma contrast plugin, so designers could fix them in one pass.
  • Meaning beyond colourAn icon or text for statuses, a filled icon for the active tab, an underline or a button style for interactive address links, and a text alternative for the personal-offer dot.
  • Invisible 44 × 44 hit areasAn invisible touch container around small elements, so the tap area grows while the visual design stays the same. For banners, the whole banner becomes the target.
  • Focus states designed firstDesigners draw the focus state for buttons, inputs, navigation, links, checkboxes, radio buttons and interactive icons. Material Design 3 served as the reference. Development implements only after the state exists in the mockup.

A phased rollout, not a wall of tickets.

  1. Fix the mockupsDesign owns contrast, colour use, target size, focus and orientation first, so development builds from correct screens.
  2. Level A in task descriptions13 level-A criteria — alt text for product images, labels and roles (4.1.2), the keyboard trap, filters that change context without confirmation (3.2.2), error prevention at checkout (3.3.1) — written into the acceptance criteria of each task.
  3. Animation and content checksMarketing checks banners for flashing (2.3.1). Content explains Silpo’s own words and abbreviations and adds short summaries to long articles (3.1.3–3.1.5).
  4. Level AA18 criteria, including autocomplete for checkout fields (1.3.5), text resize (1.4.4), reflow (1.4.10) and status messages for screen readers (4.1.3).
  5. Level AAA — only with evidenceSurvey users with disabilities first, then decide which AAA criteria are worth the cost.

The app plan followed the same logic in four steps: fix the mockups, implement 23 “Must” practices, remove every “Never” pattern, then add the “Should” practices.

The work ran alongside the Silpo Design System, where WCAG 2.1 AA was a requirement from day one. The guidelines gave designers and developers one shared reference instead of personal readings of WCAG.

What I took from it.

  • An audit is a plan, not a listFindings only help when each one has an owner, a level and a place in the delivery order.
  • Fix the system, not the screenMost findings repeated on every page. Tokens for colour, a 44 px target rule and a focus pattern remove them at the source.
  • Design goes firstDevelopers cannot build a focus state that nobody drew. Accessibility starts in the mockup.
  • I kept goingThe same standard became an entry requirement in the Silpo Design System and is written into the requirements of the BitSvit platform. In 2024 I completed a web accessibility course at Diia.Education.
